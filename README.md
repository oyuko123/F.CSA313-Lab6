# Лаборатори №6: Тест тохиолдол боловсруулах — Category-Partition ба PICT

**Оюутны нэр:** Т. Оюунжаргал

## 1. Зорилго

Энэхүү лабораторийн ажлаар банкны шилжүүлгийн функцэд Category-Partition аргаар тестийн сонголт, төлөөлөх утга, хязгаарлалт болон тестийн спецификаци боловсруулав. Мөн Microsoft PICT хэрэгслээр pairwise болон three-way тестийн багц үүсгэж, гараар боловсруулсан спецификацитай харьцуулсан.

## 3. Хэсэг A — Category-Partition

### 3.1. Алдааны давуу эрэмбэ

Олон алдаа нэг хүсэлтэд зэрэг тохиолдвол тестийн oracle тодорхой байхын тулд дараах давуу эрэмбийг сонгов:

1. `ERROR_NO_FROM`
2. `ERROR_FROZEN`
3. `ERROR_NO_TO`
4. `ERROR_SAME_ACCOUNT`
5. `ERROR_BAD_AMOUNT`
6. `ERROR_INSUFFICIENT`
7. `ERROR_LIMIT`
8. Бүх шалгалт амжилттай бол `201 {"result":"OK"}`

Энэ эрэмбэ нь лабораторийн тестийн загварт ашигласан таамаглал бөгөөд бодит системийн батлагдсан зан төлөв биш.

### 3.2. Сонголт ба төлөөлөх утгууд

| Параметр | Сонголт | Төлөөлөх утга |
|---|---|---|
| From | Хүчинтэй | Байгаа, царцаагаагүй данс |
| From | Царцаагдсан [ERROR] | Байгаа боловч царцаасан данс |
| From | Байхгүй [ERROR] | Бүртгэлгүй дансны ID |
| To | Хүчинтэй | Эх данснаас өөр, байгаа данс |
| To | Байхгүй [ERROR] | Бүртгэлгүй хүлээн авагчийн ID |
| To | Эх данстай ижил [ERROR] | From болон To ижил ID |
| Amount | Хэвийн | Эерэг, үлдэгдэл болон лимитэд багтах дүн |
| Amount | Тэг [ERROR] | 0 |
| Amount | Үлдэгдлээс их [ERROR] | Шилжүүлгийн дүн дансны үлдэгдлээс их |
| Amount | Лимитээс их [ERROR] | Өдрийн лимитээс хэтэрсэн дүн |
| Currency | Ижил | Дансны валюттай ижил |
| Currency | Өөр | Дансны валютаас өөр, ханшийн хөрвүүлэлт шаардлагатай |

**Далд орчны сонголтууд:** эх дансны үлдэгдэл, тухайн өдрийн өмнөх шилжүүлгийн нийт дүн, өдрийн лимитийн үлдсэн хэмжээ, валютын ханш, дансны царцаалтын төлөв. Эдгээрийг тестийн setup хэсэгт тодорхой зааж өгнө.

### 3.3. Хязгаарлалт ба тэмдэглэгээ

| Сонголт | Тэмдэглэгээ | Үндэслэл |
|---|---|---|
| From = Valid | [SINGLE] | Амжилттай шилжүүлгийн суурь нөхцөл. |
| From = Frozen | [ERROR] | Царцаасан данснаас шилжүүлэг хийхийг хориглоно. |
| From = Missing | [ERROR] | Эх данс олдохгүй үед алдаа буцаана. |
| To = Valid | [SINGLE] | Хүлээн авагч данс хүчинтэй байх ёстой. |
| To = Missing | [ERROR] | Хүлээн авагч данс байхгүй үед алдаа буцаана. |
| To = SameAsFrom | [ERROR] | Нэг данс руу өөрөөс нь шилжүүлэхийг хориглоно. |
| Amount = Normal | [SINGLE] | Хүчинтэй шилжүүлгийн дүнг төлөөлнө. |
| Amount = Zero | [ERROR] | Дүн тэг байж болохгүй. |
| Amount = OverBalance | [ERROR] | Үлдэгдэл хүрэлцэхгүй. |
| Amount = OverLimit | [ERROR] | Өдрийн лимит хэтэрсэн. |
| Currency = Same | [SINGLE] | Валютын хөрвүүлэлт шаардлагагүй. |
| Currency = Different | [IF/property] | Өөр валюттай үед ханшийн хөрвүүлэлт хийж, хөрвүүлсний дараах дүнгээр шалгана. |

[SINGLE] тэмдэглэгээг суурь буюу эерэг тохиолдлын утгыг тэмдэглэхэд хэрэглэв. Алдааны нөхцөлүүдийг боломжтой үед тус тусад нь шалгаж, давхар алдааны тохиолдлыг тусгайлан тодорхойлно.

### 3.4. Хослолын тооцоо

Параметрүүдийн утгын тоо:

- From: 3
- To: 3
- Amount: 4
- Currency: 2

Хязгаарлалтгүй бүрэн олонлог:

`N = 3 × 3 × 4 × 2 = 72`

Дараах хязгаарлалтыг ашиглав:

- IF From = Missing THEN Amount = Normal
- IF To = Missing THEN Amount = Normal

From = Missing үед Amount-ийн гурван буруу утгыг хориглоно: `3 × 2 × 3 = 18` хослол.
To = Missing үед мөн 18 хослол хориглоно. Гэхдээ хоёр нөхцөл зэрэг биелсэн үед 6 хослол давхар тоологдсон тул:

`72 − (18 + 18 − 6) = 42`

Иймээс хязгаарлалтын дараах хүчинтэй олонлогийн тоо:

**72 → 42**

Энэ нь бүх боломжит хослолын тооцоо юм. PICT-ийн бодит pairwise мөрийн тоо нь бүрэн олонлогийн хэмжээнээс өөр ойлголт болно.

### 3.5. Тестийн спецификаци

| № | From | To | Amount | Currency | Хүлээгдэх үр дүн |
|---:|---|---|---|---|---|
| 1 | Valid | Valid | Normal | Same | 201 `{"result":"OK"}` |
| 2 | Missing | Valid | Normal | Same | 200 `ERROR_NO_FROM` |
| 3 | Frozen | Valid | Normal | Same | 200 `ERROR_FROZEN` |
| 4 | Valid | Missing | Normal | Same | 200 `ERROR_NO_TO` |
| 5 | Valid | SameAsFrom | Normal | Same | 200 `ERROR_SAME_ACCOUNT` |
| 6 | Valid | Valid | Zero | Same | 200 `ERROR_BAD_AMOUNT` |
| 7 | Valid | Valid | OverBalance | Same | 200 `ERROR_INSUFFICIENT` |
| 8 | Valid | Valid | OverLimit | Same | 200 `ERROR_LIMIT` |
| 9 | Valid | Valid | Normal | Different | 201 `{"result":"OK"}` |
| 10 | Missing | Missing | Normal | Same | 200 `ERROR_NO_FROM` |
| 11 | Frozen | Missing | Normal | Same | 200 `ERROR_FROZEN` |
| 12 | Valid | Valid | OverBalance | Different | 200 `ERROR_INSUFFICIENT` |

Давхар алдааны №10 тестэд `ERROR_NO_FROM` нь `ERROR_NO_TO`-оос өмнө шалгагдана. №11 тестэд `ERROR_FROZEN` нь `ERROR_NO_TO`-оос өмнө шалгагдана. Эдгээр oracle нь дээр тогтоосон давуу эрэмбийн таамаглалд үндэслэнэ.

## 4. Хэсэг B — PICT

### 4.1. Browser загвар

Browser моделийн параметрүүд:

- Browser: Allow, Restrict, Block
- Cookies: Allow, Restrict, Block
- Popups: Yes, No
- Addons: Yes, No
- Attacks: Yes, No
- Forgeries: Yes, No

Бүрэн боломжит хослол: `3 × 3 × 2 × 2 × 2 × 2 = 144`.

| Туршилт | PICT-ийн мөрийн тоо |
|---|---:|
| Browser 2-way | 10 |
| Browser 3-way | 20 |
| Бүрэн олонлог | 144 |

PICT-ийн 2-way үр дүн 10 мөр бөгөөд лекцийн гараар боловсруулсан 9 мөрөөс нэгээр олон байна. PICT greedy алгоритм ашигладаг тул хамралтыг хангах хамгийн цөөн мөрийг заавал гаргахгүй. 3-way загвар 20 мөр гаргасан бөгөөд энэ нь 144 боломжит бүрэн хослолоос цөөн.

Үр дүнгийн файлууд: `results/browser-2way.txt`, `results/browser-3way.txt`.

### 4.2. Шилжүүлгийн PICT загварууд

| Загвар | Тестийн мөр | Тайлбар |
|---|---:|---|
| transfer-nc.model | 13 | Хязгаарлалтгүй загвар |
| transfer.model | 13 | IF хязгаарлалттай загвар |
| transfer-neg.model | 16 | Сөрөг утгын тэмдэглэгээтэй загвар |

PICT-ийн бодит гаралтын мөрийн тоог толгой мөрийг хасаж тооцов. Хязгаарлалттай загварын мөрийн тоо буураагүй боловч тестийн бүрдэл өөрчлөгдсөн.

Сөрөг утгуудыг `~` тэмдэглэгээгээр тодорхойлсноор PICT нэг мөрөнд хамгийн ихдээ нэг сөрөг утга оруулсан. Ингэснээр нэг тестийн мөрөнд олон алдааны нөхцөл зэрэгцэж, эхний алдаа бусдыг далдлах эрсдэлийг бууруулна.

Үр дүнгийн файлууд:

- `results/transfer-nc.txt`
- `results/transfer.txt`
- `results/transfer-neg.txt`

### 4.3. Бодит тест кейсүүд

#### TC-01 — Амжилттай шилжүүлэг

transfer-neg.txt-ийн 1-р тестийн мөр — Valid, Valid, Normal, Same.
- **Setup:** A дансны үлдэгдэл 100,000₮; өдрийн лимитийн үлдэгдэл 200,000₮; B данс хүчинтэй; хоёр данс ижил валюттай.
- **Оролт:** `{"from":"A","to":"B","amount":10000,"currency":"MNT"}`
- **Oracle:** HTTP 201, `{"result":"OK"}`.

#### TC-02 — Эх данс байхгүй

transfer-neg.txt-ийн 8-р тестийн мөр — ~Missing, Valid, Normal, Same.
- **Setup:** `UNKNOWN` ID-тай данс бүртгэлгүй; B данс хүчинтэй.
- **Оролт:** `{"from":"UNKNOWN","to":"B","amount":10000,"currency":"MNT"}`
- **Oracle:** HTTP 200, `{"result":"ERROR_NO_FROM"}`.

#### TC-03 — Шилжүүлгийн дүн үлдэгдлээс их

transfer-neg.txt-ийн 3-р тестийн мөр — Valid, Valid, ~OverBalance, Different.
- **Setup:** A дансны үлдэгдэл 5,000₮; B данс хүчинтэй; өдрийн лимит хангалттай.
- **Оролт:** `{"from":"A","to":"B","amount":10000,"currency":"MNT"}`
- **Oracle:** HTTP 200, `{"result":"ERROR_INSUFFICIENT"}`.

Эдгээр тест кейс нь тодорхойлолтод суурилсан загварын жишээ бөгөөд бодит API дээр ажиллуулсан үр дүн биш.

## 5. Дүгнэлт

Category-Partition арга нь функцийн оролт, сонголт, алдааны семантикийг системтэй тодорхойлоход тохиромжтой байв. Давуу эрэмбэ тогтоосноор олон алдаа зэрэг тохиолдох үеийн хүлээгдэх үр дүнг тайлбарлах боломжтой болсон. Харин PICT нь параметрүүдийн утгын хослолыг автоматаар үүсгэж, pairwise хамралтад чиглэсэн тестийн багц гаргасан. PICT-ийн greedy алгоритм хамгийн цөөн мөрийг заавал сонгохгүй тул гарсан мөрийн тоог гараар хийсэн загвартай харьцуулах шаардлагатай. Хязгаарлалттай загвар нь мөрийн тоог заавал багасгахгүй боловч тестийн утгын хослолд нөлөөлдөг. Сөрөг утгын `~` тэмдэглэгээ нь нэг мөрөнд олон алдааны нөхцөл зэрэг орохыг багасгасан. Гэсэн хэдий ч `~` тэмдэглэгээ нь хүлээгдэх алдааны кодыг өөрөө тодорхойлохгүй. Гараар боловсруулсан спецификаци нь алдааны нөхцөл, oracle-ийг ойлгомжтой тайлбарлахад илүү тохиромжтой. PICT нь олон параметрийн хослолын хамралтыг автоматжуулахад илүү тохиромжтой. Хамгийн их бодол шаардсан алхам нь алдааны давуу эрэмбэ, хязгаарлалтыг тогтоож, тэдгээрийг бодит тестийн oracle-той уялдуулах явдал байв.
